ARCHITECTURE RESPONSIBILITIES

module
- Feature/module-level UI and management areas.

component
- Reusable UI components.

layout
- Overall page/interface structures.

controller
- Coordinates actions and feature flow.

function
- Reusable operations and functions.

logic
- Business rules and decision-making logic.

service
- Communication with Supabase and other external services.

supabase
- Database migrations, backend functions, and security policies.

style
- Global visual system, themes, typography, and responsive rules.

utility
- Shared helpers, formatting, and constants.

documentation
- Project architecture, database, security, and development documentation.

IMPORTANT RULES

1. This is a proposed architecture only.
2. Do not create these folders/files until the project owner explicitly authorizes implementation.
3. The final structure may be adjusted after Database Schema, security, and application architecture are finalized.
4. No website content/data should be placed into source-code files.
5. File and folder names must remain lowercase.
6. Names must clearly match the responsibility of the file or folder.
7. This file does not override PROJECT_REQUIREMENTS.txt.

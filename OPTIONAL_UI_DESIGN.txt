DALIMGARI VILLAGE WEBSITE - OPTIONAL UI/DESIGN DIRECTION

STATUS
This file contains optional design/interface defaults. It is not the primary project requirements file. It may be changed or replaced later according to the project owner's decisions.

1. Overall UI style
- Modern, clean, professional, simple.
- Avoid unnecessary visual complexity.
- Keep the interface understandable for a non-technical administrator.

2. Design approach
- Mobile-first and fully responsive.
- Adapt appropriately to mobile, tablet, and desktop/web viewports.

3. Public homepage
- Main structure: Header, Banner/Hero, Body, Footer.
- Left sidebar is part of the homepage layout.
- Sidebar is hidden by default and opens through a sidebar button.

4. Sidebar
- Mobile: collapsible/overlay sidebar.
- Desktop/web: collapsible sidebar as appropriate.
- Admin profile information appears at the top.
- Navigation uses clear icon and text labels.

5. Admin dashboard
- Layout: sidebar + top header + content area.
- Responsive summary cards, forms, tables/lists, and management controls.
- Main modules use a consistent management pattern: form -> save -> records/list -> edit/delete.

6. User dashboard
- Uses the same overall design system as the Admin Dashboard.
- Contains only user-specific functions and modules.
- Permission-based additional functions may appear dynamically.

7. Visitor interface
- Public Website access without a dashboard.

8. Navigation
- Clear responsive navigation for Header, Sidebar, Body, Footer, Posts, and Dynamic Pages.
- Dynamic Pages appear as responsive tabs/buttons at the top-left of the Body.
- Separate bottom navigation is not required initially; the sidebar is the primary mobile navigation.

9. Color system
- Colors are dynamic.
- Approved color settings are managed through the customization module.

10. Font system
- Font settings are dynamic.
- Default typography must be suitable for Bengali and readable in English.

11. Theme mode
- Automatic Light/Dark mode selection.
- Manual Light/Dark mode switch.

12. Post UI
- Responsive card/grid presentation.
- Album-grouped view when an album is assigned.
- Individual media presentation when required.
- Post status and visibility should be clearly represented.

13. Page UI
- Responsive tabs/buttons for page navigation.
- Clear page title and content presentation.
- Page visibility and ordering should be reflected in navigation.

14. Authentication UI
- Simple, mobile-friendly Login and Registration screens.
- Support Google and Email/Phone + Password according to the authentication requirements.

15. Forms
- Consistent input, select, textarea, media selector, validation, and save patterns.
- Labels and controls must be understandable without technical knowledge.

16. Tables and lists
- Desktop/web: table where appropriate.
- Mobile: responsive card/list representation when a table would be difficult to use.

17. Modals and confirmations
- Use confirmation dialogs before destructive actions such as delete, reset, and restore.

18. Loading state
- Consistent loading indicator or skeleton pattern.
- Loading messages/design can be configured through the System module.

19. Error state
- Clear, user-friendly error presentation.
- Error messages/design can be configured through the System module.

20. Empty state
- Clear empty-data presentation with useful guidance where appropriate.
- Empty-state messages/design can be configured through the System module.

21. Notifications
- Use unobtrusive toast/alert feedback for save, update, delete, success, and error actions.

22. Animation
- Use small, fast, purposeful transitions.
- Avoid excessive animation that harms performance or usability.

23. Accessibility
- Readable typography.
- Appropriate contrast.
- Touch-friendly controls.
- Keyboard-friendly interaction on web/desktop where applicable.

24. Profile UI
- Profile image, name, email, and applicable account information should be presented clearly.

25. Customization interface
- Theme, font, color, and approved visual settings are managed from the customization module.
- Changes should be reflected consistently throughout the applicable interface.

26. UI consistency
- Use a shared design system for buttons, forms, cards, dialogs, tabs, spacing, typography, tables, alerts, and other common UI elements across the Public Website, Admin Dashboard, and User Dashboard.
